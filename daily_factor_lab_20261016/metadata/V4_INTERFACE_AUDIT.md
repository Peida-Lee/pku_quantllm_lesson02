# V4 界面审查与修复记录

审查日期：2026-10-17，Asia/Shanghai。范围为本地研究工作台、策略积木和任务状态接口。仅使用原 `feathers.zip` 及其派生研究结果；此记录不构成科学结果验收、真实 ST 剔除或实盘成交证明。

## 已在 authored content 修复

1. **快照和动态接口混用。** `ResearchWorkbench.jsx` 以前根据 study/time/count 等弱版本键决定使用 API 元数据，表格及图表却优先使用冻结 query rows。同大小修订存在数值与元数据不一致风险。现有研究结果全部以冻结 `snapshot.research` 为准；API 仅用于状态和新版本提示。优先比较 `snapshot_revision`，旧版无 revision 时比较完整保存对象。V4 同样仅使用 `snapshot.research_v4` 与同批 reviewed queries。
2. **任意后台空闲被当作研究完成。** 以前全局 `busy` 从真变假就显示研究完成。现在旧研究只追踪 `job_kind=research_v3`、非空 `job_id` 及对应终态；无身份不推断完成。V4 只接收 `job_kind=research_v4` 的专用进度；终态不会使动态 API 数值自动替换冻结证据。
3. **策略 selection 默认值改变继承语义。** 前端以前为导入文件缺省的 `top_n/rebalance` 填 100/weekly，覆盖后端继承当前 Config 的设计。现在缺省字段保持省略，控件显示继承参数；目标只数清空或频率选择“继承实验参数”可恢复继承。提交时仅覆盖 JSON 中明确提供的字段。
4. **校验旧响应覆盖新草稿状态。** 策略静态校验增加请求序号、AST/Config 指纹与单调版本号；草稿或配置变化后，即使又改回原内容，过期响应也不会把当前文档标为通过或用于继续提交。加载/导入同样防止过期响应覆盖后续编辑。运行冻结校验时的策略和 Config，后续编辑不改变本次任务。控件明确标为“当前版本静态校验通过”，不宣称已完成执行校验。
5. **部分操作异常不可见。** `patch` 捕获策略大小/深度等编辑错误并显示。研究队列首次连接失败现在优先显示连接错误，避免一直显示读取中。
6. **首次状态与空参数误用。** 队列状态首次未读、失联或返回非法活动身份时禁止提交长任务；accepted 身份同步回传父级，旧轮询不能覆盖新提交状态。数值框清空保留空白，显式 0 与缺失区分；前端校验有限值、整数、日期及范围，并在提交前拒绝 legacy 与正提前退出天数的组合。目标只数不表述为实际持仓硬上限。
7. **表内排序覆盖外部排序。** 共享 DataTable 保留自己的临时表头排序、分页和搜索状态。此前用户点过 2025 表头后再切顶部 2024 排序，表内旧 order 仍可能覆盖顶部选择。现在全局筛选/排序改变时重新挂载台账表，重置这些局部状态；提示也明确表头可临时重排，2025 排序仍为回顾性探索。
8. **导入互锁的静默拒绝。** 以前正在校验/保存时仍能点击导入、模板与已保存策略，操作锁可能无提示地丢弃文件选择。现在相关入口在 working 时禁用，文件对话框竞态到达时明确提示重新导入，不静默丢弃。

## V4 界面契约

- 保留原三个 tab、稳定 app ID、现有布局及 Data shared runtime。新增 `factor-explorer` tab，不替换 V3 研究入口。
- reviewed queries 为 `research_v4_candidates`、`research_v4_curves`、`research_v4_failures`，来源和协议由生产 snapshot 写入。动态 API 不补充、覆盖或拼接冻结数值。
- 全候选按家族、股票池、目标只数、调仓频率、完整度及研究筛选状态过滤；支持分组覆盖表和全文公式搜索。默认按 2024 夏普排序。2025 收益、夏普、回撤及压力收益排序明确标为回顾性探索。
- 四情景齐全要求后端 `all_required_runs_complete=true` 且每项 `status=success`、收益为有限数。失败、缺失、未测及未知均不补零。
- 研究筛选通过以精确后端状态 `通过研究筛选（仍有数据限制）` 和全部后端门槛为依据：完整性、独立数值、各情景无减记及通过模型卖出退出、2025 基准/费用/容量正收益、两个半年均正、容量平均仓位至少 25%、各情景回撤不超过 40%、费用及容量综合压力检查。缺证据保留阻塞原因，不自行放宽门槛。
- 同一候选的 2024/2025 四情景、公式、窗口、实际检查和分季原值可查。曲线 series 包含 `period_role` 与 `scenario`，防止 2025 与延伸期的同名 base 混线。
- 任务进度显示后台 `completed/total`、失败数、阶段、更新时间和估计剩余时间。启动后的计划总量等待后台返回，不用固定 120 候选或前端推算数代替。
- 独立明细入口仅提交明确所选 `experiment_id`。后台仍负责全局互斥和实际运行校验。
- `research_v4_neighbors` 为可选的事后描述卡。query source 的 study_id、source_snapshot_revision 必须匹配当前冻结研究，script_sha256 必须存在且格式有效；生产附加器另核对脚本实际 hash。只选择当前 experiment_id 的原始汇总，重复记录不聚合，rows 非数组则失败关闭。分期显示正收益比例、中位/最差收益和 observed/expected/failed/unknown 分母；2024 夏普分母单列。缺失显示“—”，不改变选型、收益或 readiness。

## 已有服务端修复与证据

这些条目已由根任务及 API 审查完成，不再列为未修复问题。证据为 [V4_API_AUDIT.md](V4_API_AUDIT.md)、[V4_API_AUDIT.json](V4_API_AUDIT.json) 与 [V4_LIVE_API_VALIDATION.json](V4_LIVE_API_VALIDATION.json)；本轮只阅读这些已保存记录，没有重复执行 HTTP 检查。

1. **持久任务身份与状态协调已实现。** accepted、queued、running、building 及终态保留 job_id/job_kind；API 与 CLI 身份分离，旧进度不能冒充新任务，重启后不把失联任务伪标完成。隔离 HTTP 测试覆盖明确绑定、未绑定、仍持锁及子进程完成但快照未完成等分支。
2. **扩展包写锁与原子写入已实现。** PACK_LOCK 包住读取、合并验证及原子写入；两个同 ID 并发请求的隔离证据显示存储 ID 一致且只保留一个 JSON 条目，原来的并发原子性风险已被覆盖。
3. **非法执行组合与参数早拒绝已实现。** 服务端在线程启动前拒绝 legacy 与提前退出/清算冲突、strict ST、非有限数值及未知字段。前端另提供 legacy 与正 wind_down_days 的早期错误提示，不依赖后台任务失败才发现。
4. **冻结身份与已审核激活门槛已实现。** V4 激活和构建要求 snapshot_ready、validation.passed、非 pilot、冻结计算源码以及原包身份匹配。邻域附加器 `v4_snapshot.py` 静态检查 study/revision/脚本 hash 后才附 reviewed query，前端再检查研究身份。
5. **证据数量与范围。** 隔离 HTTP 共有 20 项通过证据，按 16+1+3 三批定向执行；14 项真实 loopback 只读/静态校验/非法请求检查也已保存为 passed=true。真实检查没有启动可运行任务、外部 AI、保存策略或额外监控研究队列。

仍须保留的边界：本服务锁不统一调度所有外部程序直接运行的旧脚本；全量日账本数值复核与详细样本逐笔复核是不同证据，不能互相替代；这些接口记录不证明浏览器渲染、真实 ST、开盘撮合或未来盈利。

## 验证边界

此前已使用官方 standalone authoring compiler 检查主页面、研究页、策略页、参数页和共享参数 helper，并执行参数边界与邻域身份边界断言。本轮只对实际修改的 FactorExplorer、StrategyBuilder、NeighborStabilityCard 三个 JSX 再做 transform 与 JavaScript parse，均通过。

最终定向静态边界验证：在内存中生成 1404 条 mock 前端记录，直接执行现有筛选/排序表达式，验证全量保留、2024 默认顺序、null 夏普后置、负收益不丢弃、家族筛选、交叉空结果、通过/完整状态筛选、候选 ID 搜索、负回撤由浅到深排序；另验证邻域 rows 非数组失败关闭，共 11 项断言通过。没有写入或展示 mock 研究结果。首次隔离脚本漏载其依赖的 metric helper，未跑完；补齐测试依赖后通过，未因此改动生产筛选逻辑。

真实浏览器渲染与交互检查仍未完成，由主任务统一执行。本轮没有构建、打开浏览器或读取实时研究进度。实际界面仍需确认：1404 条分页与空结果可读性、来源检查器与图表同版本、临时表头排序的重置、导入/校验/提交的视觉互锁、旧响应不误标新草稿，以及继承 Config 后实际运行参数一致。
